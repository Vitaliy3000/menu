# Меню

Статический сайт с рецептами и техкартами дней готовки. Vite + TypeScript + Preact, данные — JSON, деплой — GitHub Pages.

- **Рецепты** — каталог с поиском, фильтрами (категория, «до 30 минут», сезон, заморозка, калорийность, питание, теги) и страницы рецептов: КБЖУ, пересчёт порций, шаги с таймерами, сезонность, хранение, заморозка, разогрев.
- **Выпечка** — хлеб, пицца и закваска: формула в граммах с пекарскими процентами (сайт считает их сам), предфермент или юдане отдельными списками, пересчёт на число форм, форма и загрузка в г/л, способы (прямой, с предферментом) переключателем, шаги с температурой и таймерами (отметки сохраняются — выпечка тянется часами), заметки с пробных выпечек, «каким должен получиться», частые ошибки. Ниже — справочник: руководство по формовому хлебу Pullman и что испечь дальше.
- **Продукты и блюда** — каталог продуктов, частей блюд, блюд и соусов. Сырое и готовое — отдельными позициями. У каждой позиции — сенсорный профиль (базовые вкусы, острота и жирность от 0 до 10, аромат по нотам), кухни, к которым она относится, оценка микроволновки от 0 до 100 — насколько после нагрева в микроволновке это похоже на только что приготовленное, — и заморозка: оценка от 0 до 100 — насколько после разморозки и лучшего способа восстановления это похоже на свежее, — что теряется, как вернуть, как заморозить, сколько месяцев держит качество и источники. Поиск по названию, группе и кухне, фильтр по группе, переключатель шкалы (заморозка или микроволновка), порог «не ниже» и сортировка по оценке выбранной шкалы; шкала сбоку показывает, сколько позиций выбранной группы в каждой полосе.
- **Техкарты** — самостоятельные планы дня готовки с уникальными названиями, без привязки к датам: закупка в итоговых объёмах, техника и условия, блюда с фасовкой и сроками, таймлайн по минутам. На телефоне — режим готовки: шаг крупно, продукты с количествами прямо в шаге, таймеры, экран не гаснет, прогресс сохраняется. Если готовят несколько человек, у каждого своя роль: свой ход работ и своя кнопка «Начать готовку» на своём телефоне, а длительность показывается общая и по каждому — сколько он на кухне и сколько из этого заняты руки (считается по шагам роли). У шага видно, в какой зоне кухни он идёт. По желанию — рацион: меню каждого человека по дням на своей вкладке в порядке дня (завтрак, перекус, обед, перекус, ужин, перекус) — откуда взять обед и ужин, сколько их греть, как приготовить завтрак и перекусы, что утром взять с собой на работу и что вечером разморозить на завтра, с итогом калорий и белка против цели. Ещё по желанию — примерная стоимость продуктов в магазине: в карточке техкарты она стоит рядом с числом дней рациона.

Фронтенд только показывает готовые данные: никакого бэкенда, планировщика или генерации техкарт на лету.

## Быстрый старт

```bash
npm install
npm run dev        # http://localhost:5173
npm run check      # данные + типы + тесты — то же, что в CI
npm run build      # сборка в dist/
```

Нужен Node.js ≥ 22.18 (скрипты в `scripts/` запускаются напрямую как `.ts`).

## Данные

```
data/
  recipes/<id>.json   # Recipe
  plans/<id>.json     # CookPlan
  bakes/<id>.json     # Bake — рецептура выпечки
  kitchen.json        # справочник кухни
  baking.json         # справочник выпечки
  foods.json          # каталог продуктов и блюд: вкус, аромат, кухни, заморозка
schemas/
  recipe.schema.json
  cook-plan.schema.json
  kitchen.schema.json
  bake.schema.json
  baking.schema.json
  foods.schema.json
```

`Recipe` и `CookPlan` — две независимые сущности. Техкарта не ссылается на рецепты и не может этого сделать: схема запрещает лишние поля, и сборка упадёт на `recipeId`. Техкарта самодостаточна — свои продукты в итоговых объёмах, своя техника и свой таймлайн, уже адаптированные под конкретные объёмы и условия.

Техкарты не привязаны к датам: у каждой уникальное название, а на сайте они идут ровно в порядке файлов в `data/plans/` — без сортировки. Сроки хранения показываются в днях, а после нажатия «Начать готовку» — конкретной датой «годен до».

Каждый файл начинается с `"$schema": "../../schemas/…schema.json"`, поэтому VS Code подсказывает поля и подсвечивает ошибки прямо при редактировании. Подробные описания полей лежат в самих схемах — их удобно отдавать и человеку, и LLM, которая готовит JSON офлайн.

### Справочник кухни

`data/kitchen.json` (схема `schemas/kitchen.schema.json`) — то, на что опираются при составлении техкарт, чтобы не повторять это в каждом промпте:

- **кто что не ест** — для каждого человека продукты с уровнем: аллергия, не ест, не любит (+ чем заменить);
- **правила техкарт** (`planRules`) — главная идея, ресторанный ужин, закупка, вкус, питание, приёмы пищи, ход дня готовки, кухня, фасовка и заморозка, сгруппированные по темам;
- **продукты и бренды** (`products`) — общие правила подбора в магазине (эмблемы, Beter Leven, био, производители), что берём всегда и чего избегаем; конкретный выбор важнее общих правил;
- **оборудование** — техника и многоразовая посуда с характеристиками;
- **хранение** — холодильник, морозилка, шкаф: объём и сколько обычно свободно;
- **излишки** (`surplus`) — продукты, которые уже есть дома в запасе: их желательно включать в меню следующих техкарт.

Расходников (пакеты, фольга, плёнка, одноразовые контейнеры) в справочнике нет: каждая техкарта перечисляет свои в `equipment` с `kind: "consumable"`. Всё, что надо купить к дню готовки, — расходники и инвентарь, которого нет на кухне, — помечается `"buy": true` и попадает в список покупок на вкладке «Продукты» отдельной группой.

Справочник показывается на странице «Кухня». Сборка публикует `kitchen.json` и схемы как обычные файлы (`/menu/kitchen.json`, `/menu/schemas/*.json`), так что LLM можно дать на них ссылки. Техкарты на справочник не ссылаются и остаются самодостаточными.

### Выпечка

`data/bakes/<id>.json` (схема `schemas/bake.schema.json`) — рецептура: формула в граммах на один замес, у муки `"flour": true`. Пекарские проценты, вес теста и загрузку формы сайт считает сам. Части, которые замешивают заранее (предфермент, юдане, автолиз), перечислены в `formula.parts`, а у ингредиента в `parts` — сколько граммов уходит в каждую; остаток идёт в финальное тесто. Способов может быть несколько (`methods`), у каждого своя форма, время, формула и этапы. Журнал пробных выпечек — `attempts`. Рецептуры ни на что не ссылаются.

`data/baking.json` (схема `schemas/baking.schema.json`) — справочник раздела: руководства (`guides`) и идеи (`ideas`).

Сладкая выпечка из обычных рецептов (категория `baking`) остаётся в рецептах.

### Каталог продуктов

`data/foods.json` (схема `schemas/foods.schema.json`) — группы (`groups`) в порядке показа и источники (`sources`). Позиция: название, кухни `cuisines` — к каким кухням относится, по убыванию характерности (нет — продукт обычен почти везде), вкус `taste` — сладость, кислота, солёность, горечь, умами, острота и жирность от 0 до 10, аромат `aroma` — до шести нот из словаря с силой от 1 до 10 (нет — без запаха); словари и якоря шкал — в описаниях `$defs` схемы. По этим профилям собирают меню под привычный вкус. Оценка микроволновки `microwaveScore` (0–100, шаг 5) — насколько позиция после нагрева в микроволновке лучшим способом близка к свежеприготовленной: 100 — можно подать в хорошем ресторане, 0 — греть нельзя; что едят холодным, оценивается по тому, что с ним сделает нагрев, сырьё — по тому, как оно готовится в микроволновке. Дальше — заморозка: оценка `freezeScore` (0–100, шаг 5; шкала — в описании поля в схеме), `months` — сколько месяцев держит качество при −18 °C (нет — замораживать не советуют или незачем), `losses` — что теряется, `recovery` — как вернуть и насколько, `method` — неочевидные шаги заморозки, `sources` — id источников (нет — оценка по аналогии с похожими продуктами). Каталог ни на что не ссылается, техкарты и рецепты на него тоже. Он тяжёлый, поэтому собирается отдельным чанком и грузится только на своей странице.

### Как добавить рецепт или техкарту

1. Скопируйте похожий файл из `data/recipes/`, `data/plans/` или `data/bakes/`.
2. Имя файла = `id` (латиница, kebab-case) — это же часть URL.
3. `npm run validate` или просто `npm run dev`: ошибки показываются в терминале и оверлеем в браузере.

### Что проверяет валидатор

`npm run validate` (и Vite-плагин при каждой сборке):

- соответствие JSON Schema (draft 2020-12, Ajv, строгий режим);
- `id` совпадает с именем файла;
- рецепт: активное время ≤ полного, диапазоны количеств, калории сходятся с БЖУ (4/9/4 ккал, допуск 15 %);
- выпечка: уникальные названия и id способов; у каждого способа название, если их несколько; в формуле есть мука, нет повторов, части существуют и используются, в часть уходит не больше, чем всего; вес теста сходится с загрузкой формы (г/л × объём, допуск 3 %, иначе предупреждение); верхние границы времени и температуры больше нижних; попытки ссылаются на свои способы. В справочнике выпечки — без повторов в идеях, у раздела руководства есть текст или пункты;
- каталог продуктов: вкус, ноты аромата и кухни — только из словарей схемы; уникальные id групп и позиций, названия без повторов (без учёта регистра и «ё»), позиции ссылаются только на существующие источники, у источников нет повторов id и ссылок, неиспользуемый источник — предупреждение;
- техкарта: уникальное название среди всех техкарт; уникальные `id` блюд, продуктов, техники и шагов; шаги ссылаются только на существующие блюда, технику и продукты этой же техкарты; шаги отсортированы по `at` и укладываются в `duration.total`; каждый продукт где-то используется, каждое блюдо где-то готовится; по шагам не расходуется больше, чем куплено (г↔кг, мл↔л↔ложки); если заданы `roles` — у каждого шага есть существующая роль, у каждого активного шага — зоны кухни (`zones`), двое не работают одновременно в подготовке, горячей зоне или фасовке (пассивные шаги зону не занимают), стадию на плите или в духовке — поставить, таймер, помешать, снять — ведёт один человек, а шаги каждого идут без промежутков: пауза — шаг отдыха с таймером (`rest`); посуда и инструменты не заняты сразу в большем числе шагов, чем их `count` (шаг блюда в посуде, где оно ждёт, — то же место); соль в шагах — только граммами: без `toTaste`, ложек, «щепотки соли» и «по вкусу»; блюдо рациона — либо обед, либо ужин (`meal`) и стоит только на своём месте; разогрев порции — способ, минуты у плиты и руками и всего (`reheat`): обед только в микроволновке, ужин — не больше 20 минут до тарелки и 15 у плиты и руками, разогрев духовки и воды не считается; проверки хода работ, посуды, соли и обедов с ужинами не касаются техкарт, которые уже готовили (`cooked`); рацион ссылается только на свои блюда, перекусы и людей, у каждого есть порция каждого блюда дня, каждый обед и ужин каждого человека лежит ровно в одном контейнере своего блюда (`packaging[].meals`, столько же, сколько `count`), а итог дня отличается от цели не больше чем на 10 % (иначе предупреждение); КБЖУ порций сходятся с калорийностью, а у блюда из рациона нет своего `nutrition` — карточка блюда показывает КБЖУ порции каждого человека.

Ошибки останавливают сборку, предупреждения только печатаются.

### Типы

TypeScript-типы генерируются из схем — схема остаётся единственным источником правды:

```bash
npm run types         # обновить src/types/*.gen.ts после правки схемы
npm run types:check   # CI: упасть, если типы устарели
```

## Анкета «Блюда на двоих»

Локальное приложение на Python без зависимостей: двое по очереди свайпают 50 блюд (вправо — нравится, влево — нет, вниз — не знаю или средне), и оно показывает, что нравится обоим и что одному нравится, а другому средне.

```bash
python3 dish-swipe/app.py   # откроет вкладку браузера; стрелки или свайп мышью
```

В колоду `dish-swipe/dishes.json` взяты блюда, которые проходят правила техкарт из `data/kitchen.json`:

- обед — только микроволновка и один контейнер, у каждого компонента оценка микроволновки в каталоге не ниже 80;
- ужин — быстрый (до 10 минут от контейнера до тарелки) или «поставил и забыл» (до 60 минут и не больше 5 действий), ничего в кипятке;
- никто из двоих их не исключает;
- у каждого замороженного компонента тарелки, включая гарнир, оценка заморозки в каталоге не ниже 80.

У блюда есть приём пищи (`meal`), подача (`serve` — как оно идёт из морозилки на тарелку и что учесть в техкарте: замены, закупку, недостающую посуду) и позиции каталога для всех замороженных компонентов (`foods`). При запуске приложение сверяет `foods` с `data/foods.json`: если позиции нет, оценка заморозки ниже 80 или у обеда оценка микроволновки ниже 80, оно не стартует. Подача ужина начинается с режима, времени и числа действий.

Фото — `dish-swipe/photos/<id>.jpg`, 960×720, у всех одна подача: обычный солидный ресторан. Автор и лицензия фото — в поле `photo` блюда.

Ответы сохраняются в `dish-swipe/results/`; в git эту папку не кладут. Совпадения считаются по последним ответам каждого человека. Если колода поменялась, то под тем же именем приложение покажет только новые блюда, а ответы на остальные возьмёт из прошлого раза; пока человек не ответил на новые, в совпадениях он не участвует.

## Деплой на GitHub Pages

Workflow `.github/workflows/deploy.yml` на каждый push в `main` проверяет данные, типы и тесты, собирает сайт и публикует его.

Один раз в репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**.

Подпапка (`/menu/`) берётся из `actions/configure-pages` автоматически, поэтому собственный домен тоже заработает без правок. Для каждой страницы рецепта и техкарты сборка кладёт свой `index.html` с правильными `<title>` и description: прямые ссылки открываются с кодом 200, а `404.html` ловит остальное.

Локально проверить сборку с подпапкой:

```bash
BASE_PATH=/menu npm run build && npx vite preview --base /menu/
```

## Устройство

```
src/
  data/index.ts          # JSON из data/ → типизированные массивы
  types/*.gen.ts         # сгенерировано из schemas/
  lib/                   # роутер, форматирование, фильтры, таймеры, прогресс, wake lock
  components/            # общие компоненты
  pages/                 # каталоги, рецепт, выпечка, техкарта
  pages/plan/            # обзор, продукты, таймлайн, режим готовки
  styles/                # токены (светлая/тёмная тема) и стили по разделам
scripts/
  data-validation.ts     # валидация (общая для CLI, Vite-плагина и тестов)
  vite-plugin-menu-data.ts
  validate-data.ts, gen-types.ts
tests/                   # Vitest
dish-swipe/              # анкета «Блюда на двоих»: Python-сервер, web/ и photos/
```

Прогресс по техкартам (отмеченные шаги и продукты, время старта), отмеченные шаги выпечки и таймеры хранятся в `localStorage` браузера. Таймеры считают время до момента окончания, поэтому переживают перезагрузку и блокировку экрана.
